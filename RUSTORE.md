# Публикация «Новеллы» в RuStore — пошагово

Приложение — Android (Capacitor-обёртка вокруг `index/js/css`, истории из `stores/` вшиты внутрь при сборке). RuStore принимает **подписанные APK или AAB**; пакет должен иметь уникальный package name, каждая следующая версия — тот же ключ подписи и больший `versionCode`.

Текущие параметры сборки: **package `ru.novella.reader`**, minSdk 24 (Android 7+), targetSdk 36 (Android 16), единственное разрешение — интернет.

> ⚠️ Прежде чем отправлять в RuStore впервые: **(1)** добавь хотя бы 1–3 готовые истории в `stores/` (пустое приложение без контента модерация отклонит — описания и скриншоты должны соответствовать тому, что реально есть в сборке); **(2)** реши, оставлять ли package `ru.novella.reader` — после первой публикации его уже не поменять. Если меняешь, правь `appId` в `capacitor.config.json` и `applicationId`/`namespace` в `android/app/build.gradle` **до** первой загрузки.

---

## 1. Как получить файлы приложения

### Вариант A — GitHub Actions (рекомендуется, ничего ставить не надо)

В репозитории настроен workflow **«Сборка Android (APK + AAB для RuStore)»**:

- Запускается сам при коммите в `main` (и вручную: GitHub → Actions → выбрать workflow → Run workflow).
- `versionCode` = номер запуска — растёт автоматически; `versionName` берётся из `package.json` (поднимай вручную: 1.0.0 → 1.1.0…).
- Результаты лежат во вкладке запуска → **Artifacts**:
  - `novella-debug-apk` — тестовый APK: скачай, поставь на свой телефон, проверь всё перед релизом.
  - `novella-release-aab` — файл для RuStore (подписанный только при настроенном ключе, см. раздел 2; без ключа workflow явно предупреждает, а AAB получится неподписанным — такой RuStore не примет).

### Вариант B — Android Studio на своём компьютере

1. `npm install` один раз, затем при каждом изменении: `npm run build:android`.
2. Открой папку `android/` в Android Studio → Build → Generate Signed App Bundle/APK → Android App Bundle.
3. Версии без CI задаются вручную в `android/app/build.gradle` (значения по умолчанию `versionCode 1`, `versionName "1.0.0"`) или параметрами `-PappVersionCode=N -PappVersionName=X.Y.Z`.

## 2. Ключ подписи (один раз, критически важно)

Без подписи RuStore файл не загрузится, а обновления принимаются **только с тем же ключом**. Потерял ключ — приложение больше никогда не обновить. Сгенерируй и храни резервную копию вне Git (менеджер паролей/зашифрованный диск).

```bash
keytool -genkeypair -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias novella
```

(`keytool` идёт с JDK/Android Studio: `…/Android Studio/jbr/bin/keytool`.)

Дальше — один из способов:

- **Для GitHub Actions** (Repository → Settings → Secrets and variables → Actions):
  - `ANDROID_KEYSTORE_BASE64` — содержимое ключа в base64: `base64 -w0 release.jks` (Windows: `certutil -encode release.jks out.txt`, убрать шапку/подвал и переносы).
  - `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`.
- **Для локальной сборки** — положи `release.jks` в `android/` и создай `android/keystore.properties`:
  ```properties
  storeFile=release.jks
  storePassword=ПАРОЛЬ_ХРАНИЛИЩА
  keyAlias=novella
  keyPassword=ПАРОЛЬ_КЛЮЧА
  ```
  Оба файла уже в `.gitignore` — проверь, что они не попали в коммит.

## 3. Карточка в RuStore Console

1. Регистрация: [console.rustore.ru](https://console.rustore.ru) через VK ID с подтверждением личности/организации (физлица публикуют бесплатно; для платных функций нужны ИП/юрлицо/самозанятый).
2. «Добавить приложение» → укажи package name `ru.novella.reader` (или свой, см. предупреждение выше).
3. Загрузи подписанный AAB из артефактов.
4. Заполни карточку (на русском):
   - **Название**: «Новелла — интерактивные истории» (или своё; не обещай того, чего в сборке нет).
   - **Краткое и полное описание** (полное — до 4 000 символов): истории с выбором, ветки и финалы, кристаллы, новые истории обновлениями. Описывай только реально работающее в этой версии.
   - **Иконка 512×512** — уже готова: `rustore/icon-512.png`.
   - **Скриншоты: минимум 3**, снятые с реальной сборки (поставь себе debug-APK и наделай): библиотека, сцена с диалогом, экран выборов (видна цена ◆), экран финала. Не используй дизайнерские макеты вместо реальных экранов.
   - **Категория**: «Книги» / «Развлечения» / «Игры → Приключения» — на твоё усмотрение.
   - **Возрастной рейтинг**: пройди анкету консоли честно по содержанию твоих историй (романтические темы обычно дают 12+/16+; откровенный контент — выше и с риском отказа).
   - **Политика конфиденциальности**: опубликуй `privacy-policy.md` из репозитория по постоянной ссылке (GitHub Pages: Settings → Pages → main, затем ссылка вида `https://<логин>.github.io/novel/privacy-policy.html` после рендера — или любой хостинг), заполнив в ней поля в `[скобках]`, и вставь URL в карточку.
   - **Контакты разработчика**: рабочий e-mail (модерация пишет туда).
5. «Отправить на модерацию». Обычно проверка занимает до ~72 часов; причины отказов и трек исправлений видны в консоли.

### Частые причины отказов — как мы их закрыли заранее

- *Другой ключ / не вырос versionCode* — подпись настраивается один раз (раздел 2), versionCode растёт сам в CI.
- *Меньше 3 скриншотов или скриншоты не из приложения* — снимй с debug-сборки на своём телефоне.
- *Нет политики конфиденциальности / ссылка не открывается* — готовый текст в репозитории, нужна только публикация по URL.
- *Лишние разрешения без объяснения* — у нас только INTERNET (загрузка картинок по ссылкам из историй; объяснение есть в политике). Остальные доступы не запрашиваются.
- *Зависимость от сервисов Google* — их нет: вход не нужен, Google SDK не используются.
- *Платежи мимо RuStore* — покупок за деньги в приложении нет (кристаллы только за рекламу/прохождение/приглашения). Если позже добавишь покупку кристаллов за деньги, понадобится RuStore Billing SDK и статус самозанятого/ИП — это отдельный этап.

## Реклама (Яндекс, РСЯ) — уже встроена

В приложение нативно подключён Yandex Mobile Ads SDK (плагин `YandexAdsPlugin.java`), блоки из твоего кабинета указаны в `js/config.js` (`CONFIG.ads`):

| Блок | ID | Где показывается |
|---|---|---|
| С вознаграждением | `R-M-20304990-1` | Магазин (+5 ◆), «не хватает кристаллов», кнопка «Удвоить награду ×2» на экране финала |
| Межстраничная | `R-M-20304990-2` | Между новеллами: при входе в историю из библиотеки и при выходе с экрана финала (не чаще раза в 2 минуты — `interstitialCooldownSec`) |
| Нативная | `R-M-20304990-3` | Карточка в нижней части библиотеки (закрывается крестиком) |

Что сделать тебе:

1. **Активация приложения в РСЯ**: в кабинете висит «Приложение в тестовом статусе» — после публикации в RuStore нажми «Добавить ссылку» и укажи ссылку на страницу приложения в RuStore. До активации реклама может отдаваться ограниченно/тестово.
2. **Проверка на телефоне**: поставь debug-APK из Actions и пройди историю — должны показаться все три формата. Диагностика интеграции SDK: `adb logcat -v brief '*:S YandexAds'` — ищи `[Integration] ... integrated successfully` по каждому типу.
3. **Карточка RuStore**: честно отметь наличие рекламы, если консоль спросит.
4. Если поменяешь блоки в кабинете — правь только ID в `js/config.js`, пересборка подхватит.

## 4. Цикл обновления с новой историей

1. Закоммить папку `stores/N/` (`story.json` + фото) в `main` (подробности: `stores/README.md`).
2. Подними `version` в `package.json`, если хочешь красивый номер (необязательно — versionCode вырастет сам).
3. Дождись зелёного запуска Actions, скачай `novella-release-aab`, проверь debug-APK на телефоне.
4. RuStore Console → приложение → Новая версия → загрузи AAB → «Что нового»: «Новая история: «Название»» → на модерацию.

---

## 5. Если сборка в Actions упала

Открой запуск → красный шаг: `npm run validate` (битая история — текст ошибки на русском), Gradle (чаще всего — опечатка в секретах подписи либо закончились минуты). Локально то же проверяется `npm run validate` и `npm run build:www` без Android Studio.
