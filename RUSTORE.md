# Публикация «Новеллы» в RuStore — пошагово

Приложение — Android (Capacitor-обёртка вокруг `index/js/css`, истории из `stores/` вшиты внутрь при сборке; сейчас внутри 6 историй). RuStore принимает **подписанные APK или AAB**; пакет должен иметь уникальный package name, каждая следующая версия — тот же ключ подписи и больший `versionCode`.

Текущие параметры сборки: **package `ru.novella.reader`**, minSdk 24 (Android 7+), targetSdk 36 (Android 16), разрешения — интернет, состояние сети и рекламный идентификатор (для рекламы Яндекса), **возрастной рейтинг — 18+** (истории №3–6).

> ⚠️ Package name `ru.novella.reader` после первой публикации уже не поменять. Если хочешь другой — правь `appId` в `capacitor.config.json` и `applicationId`/`namespace` в `android/app/build.gradle` **до** первой загрузки в магазин.

---

## 1. Как получить файлы приложения

### Вариант A — GitHub Actions (рекомендуется, ничего ставить не надо)

Workflow **«Сборка Android (APK + AAB для RuStore)»** запускается сам при коммите в `main` или `arena/**` (если изменён код/истории) и вручную: GitHub → **Actions** → выбрать workflow → **Run workflow**.

- `versionCode` = номер запуска — растёт автоматически; `versionName` берётся из `package.json` (поднимай вручную: 1.0.0 → 1.1.0…).
- Готовые файлы лежат в **Releases → `app-latest`** (и в Artifacts запуска):

  | Файл | Что это |
  |---|---|
  | `novella.apk` | Тестовая (debug) сборка: поставить на свой телефон и проверить перед релизом. В магазин не грузится. |
  | `novella-release.apk` | **Релизный APK для RuStore** — подписанный, если настроены секреты (раздел 2). Рекомендуемый файл для загрузки в магазин. |
  | `novella.aab` | То же приложение в формате AAB для RuStore (тоже требует секретов подписи). |

  Для нашей сборки APK и AAB весят одинаково (~30 МБ: картинок историй 20 МБ + код; нативных библиотек под разные процессоры нет, резать под устройства нечего) — загружай APK: это ровно тот файл, который можно перед загрузкой поставить себе на телефон.

### Вариант B — Android Studio на своём компьютере

1. `npm install` один раз, затем при каждом изменении: `npm run build:android`.
2. Открой папку `android/` в Android Studio → Build → Generate Signed App Bundle/APK.
3. Версии без CI задаются параметрами `-PappVersionCode=N -PappVersionName=X.Y.Z` (по умолчанию `1` / `"1.0.0"`).

## 2. Подпись приложения — пошагово (один раз, критически важно)

RuStore не принимает неподписанные файлы, а обновления — **только с тем же ключом**. Ключ подписи — это «паспорт» приложения: потерял файл ключа или пароли → приложение в магазине больше никогда не обновить (придётся публиковать заново с другим package name, потеряв карточку и аудиторию).

> ⛔ Никогда не отправляй файл ключа, его base64 и пароли никому — в том числе в чаты с ИИ. Единственное место для них — секреты твоего GitHub (шаг 4) и твои резервные копии. В Git ключ не коммитится (он в `.gitignore`, но проверяй `git status`).

### Шаг 1. Создать ключ на своём компьютере

**Способ 1 — Android Studio (без командной строки):**

1. Открой любой Android-проект (удобно — папку `android/` этого репозитория).
2. Меню **Build → Generate Signed App Bundle or APK…** → Next.
3. Кнопка **Create new…** под полем Key store path:
   - **Key store path**: куда сохранить, например `novella-release.jks` (вне папки репозитория — лучше отдельная папка для ключей).
   - **Password** (хранилища): придумай надёжный пароль и сразу запиши его.
   - **Alias**: `novella`.
   - **Password** (ключа): можно тот же, что у хранилища, — проще не запутаться. Если другой — запиши отдельно.
   - **Validity (years)**: `30`.
   - **First and Last Name**: твоё имя; остальные поля сертификата — по желанию.
4. OK. Дальше саму сборку можно отменить (Cancel) — файл ключа уже создан, он нам и нужен.

**Способ 2 — командная строка** (нужен JDK; `keytool` также лежит внутри Android Studio: `…/Android Studio/jbr/bin/keytool`):

```bash
keytool -genkeypair -v -keystore novella-release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias novella
```

`keytool` попросит пароль хранилища (дважды), задаст вопросы для сертификата (имя — своё, остальные поля можно пропускать Enter/точкой) и пароль ключа (Enter = тот же, что у хранилища). Срок 10000 дней ≈ 27 лет.

### Шаг 2. Сделать резервные копии

Скопируй **файл `.jks` + пароли** минимум в два независимых места: например, менеджер паролей (файл как вложение + пароли заметкой) и зашифрованный архив на флешке/в облаке. Проверь, что копии открываются.

### Шаг 3. Закодировать ключ в Base64 одной строкой

В папке с файлом ключа:

- **Windows (PowerShell)**:
  ```powershell
  [IO.File]::WriteAllText("$PWD\keystore-base64.txt", [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\novella-release.jks")))
  ```
- **macOS**: `base64 -i novella-release.jks -o keystore-base64.txt`
- **Linux**: `base64 -w0 novella-release.jks > keystore-base64.txt`

На выходе — `keystore-base64.txt`: одна длинная строка без пробелов и переносов. (Вариант через `certutil -encode` на Windows тоже работает, но там вручную убирать строки `-----BEGIN/END CERTIFICATE-----` и переносы.)

### Шаг 4. Добавить 4 секрета в GitHub

Открой `github.com/kirillpetrov08/novel` → **Settings → Secrets and variables → Actions → New repository secret** — и создай по очереди:

| Имя секрета | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | всё содержимое `keystore-base64.txt` (одной строкой) |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища с шага 1 |
| `ANDROID_KEY_ALIAS` | `novella` (alias с шага 1) |
| `ANDROID_KEY_PASSWORD` | пароль ключа с шага 1 (часто совпадает с паролем хранилища) |

### Шаг 5. Запустить сборку

GitHub → **Actions → «Сборка Android (APK + AAB для RuStore)» → Run workflow** (выбери ветку, где актуальный код) — или просто напиши агенту «секреты добавил», он запустит и проверит логи.

### Шаг 6. Проверить, что подпись применилась, и забрать файлы

- В успешном запуске **нет** предупреждения «Секреты подписи не заданы — релизные APK и AAB будут НЕподписанными», а шаг «Настроить подпись релиза» выполнен.
- Файлы — **Releases → `app-latest`**: `novella-release.apk` (его грузим в RuStore) и `novella.aab`.
- По желанию локальная проверка сертификата (Android SDK build-tools): `apksigner verify --print-certs novella-release.apk` — покажет твой сертификат. При загрузке в RuStore консоль также покажет отпечаток (SHA-256) — при каждом обновлении он должен совпадать.
- Дальше подпись работает сама: каждая CI-сборка подписывается этим ключом, шагов повторять не нужно.

### Частые ошибки

- **Base64 с переносами/пробелами** (скопировался кусками) → шаг настройки подписи или Gradle упадут. Должна быть одна строка.
- **Перепутаны пароли**: `ANDROID_KEYSTORE_PASSWORD` — от хранилища, `ANDROID_KEY_PASSWORD` — от ключа.
- **Опечатка в alias** → Gradle: `Key ... not found`. Alias должен совпадать с шагом 1 символ в символ.
- **Другой ключ для обновления** → RuStore отклонит версию. Всегда один и тот же `novella-release.jks`.

### Альтернатива для локальной сборки

Положи `novella-release.jks` в `android/` и создай `android/keystore.properties`:

```properties
storeFile=novella-release.jks
storePassword=ПАРОЛЬ_ХРАНИЛИЩА
keyAlias=novella
keyPassword=ПАРОЛЬ_КЛЮЧА
```

Оба файла в `.gitignore`. Gradle подхватит подпись автоматически и в Android Studio, и из командной строки.

## 3. Карточка в RuStore Console

1. Регистрация: [console.rustore.ru](https://console.rustore.ru) через VK ID с подтверждением личности (физлица публикуют бесплатно; для платных функций нужны ИП/юрлицо/самозанятый).
2. «Добавить приложение» → package name `ru.novella.reader`.
3. Загрузи подписанный **`novella-release.apk`** из Releases → `app-latest` (или `novella.aab` — по вкусу).
4. Заполни карточку (на русском):
   - **Название**: «Новелла — интерактивные истории».
   - **Краткое описание**: «Романтические визуальные новеллы, где каждый твой выбор меняет финал».
   - **Полное описание** (до 4 000 символов): готовый текст собран вместе с материалами карточки (описание 6 историй, механика выборов и кристаллов, пометка 18+).
   - **Иконка 512×512** — готова: `rustore/icon-512.png`.
   - **Скриншоты** — готовы: 5 штук 1080×1920 с реальной сборки (библиотека, карточка истории, сцена, экран выборов, финал). Порядок загрузки: библиотека → история → диалог → выборы → финал. Есть также промо-баннер 1280×720.
   - **Категория**: «Развлечения» или «Книги» — на твоё усмотрение.
   - **Возрастной рейтинг**: **строго 18+** (истории №3–6 — чувственная романтика для взрослых; анкету консоли заполняй честно по содержанию).
   - **Политика конфиденциальности**: опубликована на GitHub Pages — https://kirillpetrov08.github.io/novel/privacy.html (исходник: `docs/privacy.html`, та же редакция — в `privacy-policy.md`). Вставь этот URL в карточку. В политике сейчас контакт — GitHub Issues; для модерации привычнее e-mail: укажи рабочий e-mail в консоли, а если захочешь заменить контакт и в политике — скажи агенту адрес, он обновит страницу.
   - **Контакты разработчика**: рабочий e-mail (модерация пишет туда).
5. «Отправить на модерацию». Обычно проверка — до ~72 часов; причины отказов и исправления видны в консоли.
6. **После публикации** сверь реальную ссылку на страницу приложения. Ожидаемая (по package name): https://www.rustore.ru/catalog/app/ru.novella.reader — она уже прописана в `js/config.js` (`CONFIG.referrals.storeUrl`) и используется в реферальных приглашениях внутри приложения. Ту же ссылку укажи в РСЯ для активации рекламы. Если RuStore выдаст другой адрес — скажи агенту, он поправит ссылку одной строкой и пересоберёт приложение.

### Частые причины отказов — как мы их закрыли заранее

- *Другой ключ / не вырос versionCode* — подпись настраивается один раз (раздел 2), `versionCode` растёт сам в CI.
- *Меньше 3 скриншотов или скриншоты не из приложения* — готовы 5 реальных экранов с текущей сборки.
- *Нет политики конфиденциальности / ссылка не открывается* — политика опубликована на GitHub Pages по постоянной ссылке (выше).
- *Лишние разрешения без объяснения* — у нас только интернет и состояние сети (загрузка рекламы) + рекламный идентификатор от SDK; в политике это объяснено.
- *Зависимость от сервисов Google* — их нет: вход не нужен, Google SDK не используются.
- *Платежи мимо RuStore* — покупок за деньги в приложении нет (кристаллы — за рекламу, прохождение и приглашения). Если позже добавишь покупку кристаллов за деньги, понадобится RuStore Billing SDK и статус самозанятого/ИП — это отдельный этап.

## Реклама (Яндекс, РСЯ) — уже встроена

В приложение нативно подключён Yandex Mobile Ads SDK (плагин `YandexAdsPlugin.java`), блоки из твоего кабинета указаны в `js/config.js` (`CONFIG.ads`):

| Блок | ID | Где показывается |
|---|---|---|
| С вознаграждением | `R-M-20304990-1` | Магазин (+5 ◆), «не хватает кристаллов», кнопка «Удвоить награду» на экране финала |
| Межстраничная | `R-M-20304990-2` | Между новеллами: при входе в историю из библиотеки и при выходе с экрана финала (не чаще раза в 2 минуты — `interstitialCooldownSec`) |
| Нативная | `R-M-20304990-3` | Карточка в ленте библиотеки между историями (закрывается крестиком) |

Что сделать тебе:

1. **Активация приложения в РСЯ**: в кабинете висит «Приложение в тестовом статусе» — после публикации в RuStore нажми «Добавить ссылку» и укажи ссылку на страницу приложения в RuStore. До активации реклама может отдаваться ограниченно/тестово.
2. **Проверка на телефоне**: поставь `novella.apk` из Releases и пройди историю — должны показаться все три формата. Диагностика интеграции SDK: `adb logcat -v brief '*:S YandexAds'` — ищи `[Integration] ... integrated successfully` по каждому типу.
3. **Карточка RuStore**: честно отметь наличие рекламы, если консоль спросит.
4. Если поменяешь блоки в кабинете — правь только ID в `js/config.js`, пересборка подхватит.

## 4. Цикл обновления с новой историей

1. Передай агенту новую историю — он закоммитит папку `stores/N/` (`story.json` + картинки) и дождётся сборки (подробности формата: `stores/README.md`).
2. Подними `version` в `package.json`, если хочешь красивый номер (необязательно — `versionCode` вырастет сам).
3. Скачай из Releases → `app-latest`: проверь `novella.apk` на телефоне.
4. RuStore Console → приложение → Новая версия → загрузи подписанный **`novella-release.apk`** (или AAB) → «Что нового»: «Новая история: «Название»» → на модерацию.

---

## 5. Если сборка в Actions упала

Открой запуск → красный шаг: `npm run validate` (битая история — текст ошибки на русском), Gradle (чаще всего — опечатка в секретах подписи, раздел 2 «Частые ошибки», либо закончились минуты). Локально то же проверяется `npm run validate` и `npm run build:www` без Android Studio.
