# Новелла — интерактивные истории в духе «Клуба Романтики»

Статичное веб-приложение: библиотека визуальных новелл с ветвящимся сюжетом, платными выборами за кристаллы, рекламой за награду и реферальной системой. Истории добавляются файлами в папку `stores/` — без правок кода.

## Стек и почему он

**Чистые HTML + CSS + JavaScript. Ноль зависимостей, ноль сборки.**

- Работает на любом статичном хостинге (GitHub Pages, Netlify, обычный сервер) и локально одной командой.
- Нечему устаревать и ломаться при обновлениях: нет npm-пакетов, нет билда.
- Системные шрифты и анимации только на `transform/opacity` → нет подзагрузок и лагов даже на слабых телефонах.
- Легко обернуть в Telegram Mini App или мобильное приложение (Capacitor) без переписывания.

## Запуск

Браузеры запрещают читать файлы папки `stores/` при открытии страницы двойным кликом (`file://`), поэтому нужен любой локальный сервер:

```bash
cd novel
python3 -m http.server 8000
# открыть http://localhost:8000
```

Для публикации: Settings → Pages на GitHub (ветка `main`, папка `/`) — приложение сразу доступно по ссылке, её же используй как реферальную базу.

> Вкладка «Импорт» в самом приложении работает и без сервера — удобно проверять истории до коммита.

## Как добавить историю

1. Получи JSON от ИИ по промпту из [`PROMPT_FOR_AI.md`](PROMPT_FOR_AI.md) (сюжет придумывает она).
2. Сохрани как `stores/N.json`, где N — следующий номер подряд (1, 2, 3, …).
3. Проверь: `node tools/validate.mjs stores/N.json`
4. Картинки (когда будут) — в `assets/` по путям из JSON.
5. Закоммить. История сама появится в библиотеке.

Подробно: [`stores/README.md`](stores/README.md) и [`STORY_FORMAT.md`](STORY_FORMAT.md).

## Что умеет приложение

- **Библиотека** с прогрессом чтения, счётчиком открытых финалов и блоком «Продолжить».
- **Плеер**: фон и персонажи сцены, печатная машинка (отключается), тап/пробел — далее, журнал прочитанного, автосохранение на каждой реплике.
- **Ветвления**: выборы ведут в разные сцены; шкалы характеристик (`effect`) влияют на доступность выборов (`requires`) и на финалы (`branch`). Финалов в истории может быть несколько.
- **Кристаллы ◆**: стартовый бонус 20, реклама +5 (с лимитами), ежедневный бонус +5, прохождение истории +20, новый финал +10. Платные выборы списываются один раз за прохождение; при нехватке — предложение рекламы с автовыбором после неё. Все цифры: `js/config.js`.
- **Рефералы**: личный код и ссылка `?ref=`, +15 ◆ новичку, +20 ◆ пригласившему после первого прохождения друга, статистика в профиле. Нюанс серверной части честно расписан в [`REFERRAL_BACKEND.md`](REFERRAL_BACKEND.md).
- **Импорт**: перетаскивание файла, выбор файла или вставка JSON с мгновенной валидацией на русском.
- **Диагностика**: битовый файл в `stores/` не ломает приложение — ошибка показывается в библиотеке с именем файла и причиной.

## Структура

```
index.html            — все экраны
css/style.css         — строгая бежевая тема, защита от переполнения текста
js/config.js          — ВСЕ цифры экономики в одном месте
js/store.js           — сохранение в localStorage, баланс кристаллов
js/backend.js         — адаптеры рекламы и рефералов (точка подключения SDK/сервера)
js/validate.js        — валидатор формата истории (браузер)
js/loader.js          — автозагрузка stores/1.json, 2.json… и импорт
js/engine.js          — игровой движок: сцены, выборы, финалы, награды
js/app.js             — UI и экраны
stores/               — СЮДА кладутся истории: 1.json, 2.json, …
  _template.json      — шаблон-каркас формата
assets/               — covers/ backgrounds/ characters/ (картинки, все опциональны)
tools/validate.mjs    — проверка историй перед коммитом (Node)
PROMPT_FOR_AI.md      — готовый промпт для ИИ-генератора историй и картинок
STORY_FORMAT.md       — техническая справка по формату
REFERRAL_BACKEND.md   — как подключить настоящие рекламу и сервер рефералов
```

## Дизайн

Строгая бежевая палитра (тёплый фон `#F7F2E7`, тёплый чёрный текст, один бронзовый акцент `#8A6D4B`), serif только в заголовках. Мобильная колонка до 480px — как настоящее приложение. Длинные названия и описания обрезаются CSS-правилами, блок диалога прокручивается внутри себя: текст не может «вылезти» за экран при любом содержании истории.
