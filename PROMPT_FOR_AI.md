# Промпт для другой ИИ: новая история, готовая к импорту

## Как пользоваться

1. Дай другой ИИ доступ к репозиторию или возможность вернуть готовую папку/ZIP.
2. Скопируй ей блок ниже целиком. По желанию заполни параметры в квадратных скобках; сюжет специально не задан — ИИ придумывает его сама.
3. Сейчас в игре осталась только история №1, поэтому новая история должна занять папку **`stores/2/`**.
4. Когда ИИ закончит, пришли мне имя её ветки или готовую папку. Я проверю пакет, пропишу арт, вырежу прозрачные спрайты персонажей, оптимизирую изображения, импортирую историю, соберу Android и дождусь зелёного CI.

## ▼ КОПИРОВАТЬ ОТСЮДА ▼

```text
Ты — сценарист, геймдизайнер и арт-директор визуальной новеллы.
Создай ОДНУ полностью оригинальную историю как ГОТОВЫЙ ПАКЕТ ДЛЯ ИМПОРТА
в Android-приложение визуальных новелл. Сюжет, персонажей, название, диалоги
и картинки придумываешь и делаешь ты. Не пересказывай существующие произведения.

ПАРАМЕТРЫ ЗАКАЗА:
- Номер папки: 2
- Жанр: [необязательно]
- Тема/сеттинг: [необязательно]
- Тон и возраст: [по умолчанию романтика 16+, без откровенных сцен]
- Длина: [по умолчанию 30–35 сцен, примерно 15–20 минут чтения]

============================================================
1. ЧТО НУЖНО СДАТЬ
============================================================

Создай ровно одну новую папку и ничего не меняй в коде приложения
и существующих историях:

stores/2/
  story.json
  cover.jpg
  art-prompts.json
  art-plan.md
  images/
    bg-*.jpg
    <ключ_персонажа>.png
    <ключ_персонажа_эмоция>.png

Если папка stores/2 уже существует, НЕ перезаписывай её: остановись и сообщи
о конфликте.

Требования к комплектности:
- 1 обложка;
- 5–7 переиспользуемых фонов;
- 12–20 изображений состояний персонажей;
- story.json уже ссылается на реальные cover, bg и PNG персонажей;
- art-prompts.json точно описывает каждый файл и фон каждой сцены;
- art-plan.md содержит человекочитаемый список файлов и «библии внешности»
  персонажей.

Если у тебя есть генерация изображений, обязательно сгенерируй и сохрани
РЕАЛЬНЫЕ файлы по точным именам ниже. Не ограничивайся списком промптов.
Если реальные картинки сделать не можешь, не притворяйся, что пакет полный:
в финальном отчёте прямо напиши «ТЕКСТ + ПРОМПТЫ, КАРТИНОК НЕТ» и всё равно
сдай корректные story.json, art-prompts.json и art-plan.md.

Если у тебя нет доступа к файловой системе, верни:
1) полный story.json одним блоком;
2) полный art-prompts.json одним блоком;
3) art-plan.md;
4) реальные изображения отдельными файлами/вложениями в том же порядке,
   что в art-prompts.json, с точными именами;
5) отчёт самопроверки.
Не сокращай JSON и не заменяй сцены многоточиями.

============================================================
2. STORY.JSON — ТОЧНЫЙ ФОРМАТ
============================================================

story.json — один корневой объект, не массив и не обёртка.

Обязательные и разрешённые поля корня:
{
  "id": "unique-latin-id",
  "title": "Название",
  "description": "2–3 предложения без спойлеров, максимум 280 символов",
  "genre": "Романтика · ...",
  "cover": "cover.jpg",
  "coverGradient": ["#E9DCC3", "#B49B72"],
  "coverSymbol": "✦",
  "tags": ["романтика"],
  "estimatedMinutes": 15,
  "start": "s1",
  "stats": { ... },
  "characters": { ... },
  "scenes": { ... }
}

Запрещено:
- поле "author" или любая пометка об авторе;
- комментарии и висячие запятые в JSON;
- id "sol-i-svet" — он уже занят первой историей;
- кириллица, пробелы и заглавные буквы в id истории, ключах stats,
  ключах characters, id сцен и именах файлов.

STATS:
- Придумай ровно 2–3 шкалы под сюжет.
- Формат: "key": { "label": "Название", "icon": "♡" }.
- Все шкалы начинаются с 0.
- effect добавляет только +1 к одной или нескольким шкалам; отрицательных
  значений и прибавок больше +1 не используй.

CHARACTERS И СОСТОЯНИЯ:
- Придумай 3–4 реальных людей, включая героиню.
- Для главных героев сделай базовый портрет и эмоциональные состояния.
  Всего в characters должно быть 12–20 записей-состояний.
- Ключ базового состояния: "heroine", "hero", "friend" и т.п.
- Ключи состояний: "<base>_smile", "<base>_laugh", "<base>_doubt",
  "<base>_brave", "<base>_tired", "<base>_blush", "<base>_hurt",
  "<base>_close" — только те эмоции, которые реально используются.
- У всех состояний одного человека name должен быть АБСОЛЮТНО одинаковым;
  color тоже одинаковый.
- image каждого состояния: "images/<его_ключ>.png".
- В dialogue/thought поле who всегда содержит БАЗОВЫЙ ключ человека,
  а не ключ эмоционального состояния.
- В show указывай ключ состояния, подходящего сцене.
- Разные люди не должны иметь одинаковый name.

SCENES:
- 30–35 сцен, id вида s1, s2, s3a, s3b, ending_<name>.
- Каждая сцена содержит:
  {
    "bg": "images/bg-....jpg",
    "bgGradient": ["#......", "#......"],
    "show": ["heroine", "hero_smile"],
    "lines": [ ... ],
    РОВНО ОДИН вариант продолжения
  }
- bgGradient обязателен у каждой сцены даже при наличии bg.
- show: от 0 до 3 ключей состояний; обычно 1–2.
- lines: 3–5 строк на сцену.
- Типы lines:
  { "type": "narration", "text": "..." }
  { "type": "dialogue", "who": "hero", "text": "..." }
  { "type": "thought", "who": "heroine", "text": "..." }
- Продолжение — ровно одно:
  A) "choices": [...]
  B) "next": "s5"
  C) "branch": [...], "next": "fallbackScene"
  D) "ending": { "title": "...", "text": "...", "badge": "..." }

CHOICES:
- Формат:
  { "text": "...", "next": "s5" }
  { "text": "...", "next": "s5", "effect": { "brave": 1 } }
  { "text": "...", "next": "s5", "crystals": 12,
    "requires": { "hero": 2 }, "effect": { "hero": 1 } }
- В одной точке 2–3 выбора.
- Всего 4–6 платных выборов с crystals; цена только 8, 10 или 12.
- Платный выбор даёт отдельную сцену, признание, улику или другой реальный бонус.
- В каждой точке хотя бы один выбор всегда бесплатный и без requires.
- Без кристаллов и без заблокированных выборов должна существовать полная
  дорога хотя бы к одному финалу.

BRANCH:
"branch": [
  { "if": { "stat": "hero", "gte": 3 }, "to": "ending_a" },
  { "if": { "stat": "brave", "gte": 2 }, "to": "ending_b" }
],
"next": "ending_c"
Поддерживаются gte, lte, eq. Fallback next обязателен.

СТРУКТУРА И ПРОХОДИМОСТЬ:
- Ровно 3 заметно разных финала.
- Схема «ствол и короткие ветки»: ветки расходятся на 1–2 сцены и сходятся.
- Первый выбор не позже второй сцены; выбор каждые 2–4 сцены.
- Первый платный выбор не раньше третьей точки выбора.
- Каждая сцена достижима от start; нет тупиков и бесконечных циклов.
- Каждый финал достижим хотя бы одним реальным маршрутом.
- Для каждого requires/branch посчитай максимум шкалы именно к этой сцене
  по допустимому маршруту; порог должен быть достижим.
- Одна строка lines максимум 220 символов.
- Один выбор максимум 60 символов.
- Русский живой язык; героиня в narration — «ты».
- Без разметки и эмодзи внутри реплик. Прямую речь внутри narration — в « ».

============================================================
3. КАРТИНКИ — ЕДИНЫЙ СТИЛЬ И РЕАЛЬНЫЕ ФАЙЛЫ
============================================================

Все картинки генерируй одной моделью/одним способом и в одном стиле.
Нельзя смешивать фотореализм, аниме/мангу и 3D.

К каждому английскому промпту дословно добавляй в конец стиль:
"semi-realistic painterly digital illustration, soft visible brushstrokes,
muted watercolor-like shading, warm beige and earthy palette, gentle diffused
light, elegant minimalist composition, cinematic, no photorealism, no anime,
no manga, no 3D render, no text, no watermark"

БИБЛИЯ ВНЕШНОСТИ:
- Для каждого человека один раз сформулируй на английском неизменяемый блок:
  возраст, лицо, волосы, глаза, кожа, телосложение и постоянная одежда.
- Копируй этот блок СЛОВО В СЛОВО в базовый портрет, все его эмоции
  и обложку. Меняться могут только эмоция, поза и небольшой предмет в руках.
- Сначала сгенерируй базовые портреты. Эмоции делай с базовым портретом
  как референсом, если твой генератор это умеет.
- Запиши все библии внешности в art-plan.md.

ОБЛОЖКА — stores/2/cover.jpg:
- JPG, вертикаль 2:3, желательно около 1000×1500.
- Героиня и ключевой персонаж/предмет, тот же стиль и внешность.
- Без названия, букв, логотипов и водяных знаков.

ФОНЫ — stores/2/images/bg-<slug>.jpg:
- JPG, вертикаль 9:16, желательно около 1080×1920.
- Только пустая локация: no people, no characters, no silhouettes.
- Нижняя треть спокойная и не перегруженная — там будут персонажи и диалог.
- 5–7 файлов на всю историю; переиспользуй их между сценами.

ПЕРСОНАЖИ — stores/2/images/<ключ_состояния>.png:
- PNG, вертикаль 3:4 или 4:5, высота желательно не ниже 900 px.
- Один человек, поясной портрет, по центру, вся голова и плечи в кадре.
- Фигура занимает примерно 70–85% высоты; руки не обрезаны краями.
- Фон строго один из двух вариантов:
  1) настоящая прозрачность PNG без нарисованной шахматной подложки; ИЛИ
  2) полностью однотонный светло-бежевый фон #EADFCB.
- За персонажем запрещены комната, окно, мебель, пейзаж, панель, градиент,
  рамка, пол и падающая тень. Мне нужен чистый силуэт для вырезания спрайта.
- Нельзя других людей. Небольшой предмет в руках допустим, если он важен сцене.
- Файл каждого состояния точно соответствует его ключу в characters.

============================================================
4. ART-PROMPTS.JSON — МАШИННЫЙ МАНИФЕСТ
============================================================

Создай stores/2/art-prompts.json строго такой структуры:
{
  "story": "stores/2",
  "style": "полная строка единого стиля из раздела 3",
  "images": [
    { "file": "cover.jpg", "type": "cover", "prompt": "..." },
    { "file": "images/bg-example.jpg", "type": "background", "prompt": "..." },
    { "file": "images/heroine.png", "type": "character", "prompt": "..." }
  ],
  "sceneBackgrounds": {
    "s1": "images/bg-example.jpg",
    "ending_a": "images/bg-example.jpg"
  }
}

Правила:
- images содержит КАЖДЫЙ реальный файл картинки ровно один раз.
- Типы только: cover, background, character.
- sceneBackgrounds содержит КАЖДУЮ сцену из story.json, включая финалы.
- sceneBackgrounds[sceneId] в точности равен scenes[sceneId].bg.
- Для character file равен image соответствующего ключа characters.
- Никаких файлов-призраков, альтернативных вариантов и неиспользуемых картинок.

В art-plan.md продублируй:
- таблицу «файл | тип | где используется | короткий смысл промпта»;
- библии внешности;
- какой моделью/способом генерировались картинки;
- список отсутствующих файлов, если пакет неполный.

============================================================
5. САМОПРОВЕРКА ПЕРЕД СДАЧЕЙ
============================================================

Молча исправь все найденные ошибки и в финальном сообщении дай цифры:
1. story.json и art-prompts.json разбираются как JSON.
2. Сцен: N; точек выбора: N; всего выборов: N; платных: N; финалов: 3.
3. Каждая сцена достижима; каждый next/to существует; тупиков и циклов нет.
4. Каждый финал достижим: перечисли по одному маршруту scene id к нему.
5. Для каждого requires/branch: порог и максимум шкалы к этой точке.
6. Подтверди бесплатный маршрут без crystals и заблокированных выборов.
7. Все who — базовые ключи из characters; все show — ключи состояний;
   все effect/requires — ключи из stats.
8. Все lines ≤220 символов; все choices ≤60 символов.
9. Картинок в манифесте: N; реальных файлов: N; отсутствующих: 0
   (или честный список отсутствующих).
10. Каждая сцена есть в sceneBackgrounds; orphan-файлов нет.
11. Все персонажи в одном стиле; фон портретов прозрачный или #EADFCB.
12. Поля author нет; пометки об авторе нет нигде.
13. Если в репозитории доступны команды, выполни:
    npm run validate
    python3 tools/wire-art.py --check
    Вторая должна показать «не хватает 0» для stores/2.

Не запускай конвертацию спрайтов и не меняй код приложения: после твоей
сдачи импорт, вырезание прозрачных WebP, оптимизацию и сборку выполнит
другой разработчик.

Теперь придумай историю и создай полный пакет stores/2.
```
