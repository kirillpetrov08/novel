# Формат истории — полная справка

Одна история = одна папка `stores/N/` (номера подряд: 1, 2, 3…): сюжет в `story.json`, фото рядом с ним. При сборке Android истории вшиваются в приложение автоматически. Шаблон-каркас: папка `stores/_template/`. Генерацией историй занимается отдельная ИИ по промпту из `PROMPT_FOR_AI.md` — этот файл является техническим источником правды о формате.

## Поля истории

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | Уникальный id: латиница, цифры, дефис. По нему хранится прогресс — после публикации не менять |
| `title` | да | Название на карточке и в плеере |
| `description` | да | 2–3 предложения без спойлеров, до ~280 символов (на карточке видно 3 строки) |
| `genre` | нет | Короткая подпись жанра |
| `cover` | нет | Обложка относительно папки истории (`cover.jpg`) или `""` → градиент |
| `coverGradient` | нет | `[HEX, HEX]` — фон обложки и запасной фон сцен |
| `coverSymbol` | нет | Один символ-эмблема поверх градиента |
| `tags` | нет | Массив тегов |
| `estimatedMinutes` | нет | Примерная длительность чтения |
| `start` | да | id первой сцены |
| `stats` | нет | Шкалы-выборы игрока: `{ ключ: {label, icon} }`, стартуют с 0 |
| `characters` | нет* | Персонажи: `{ ключ: {name, color, image} }`. *Нужны, если в строках есть `who` |
| `scenes` | да | Словарь сцен по id |

`story.json` также может содержать массив историй или `{ "stories": [...] }` — приложение разберёт все три формы (обычно нужна одна история на папку).

## Сцена

```json
"s4": {
  "bg": "images/bg-02.jpg",
  "bgGradient": ["#EFE6D4", "#D8C7A8"],
  "show": ["heroine", "hero"],
  "lines": [
    { "type": "narration", "text": "Текст от автора." },
    { "type": "dialogue", "who": "hero", "text": "Реплика." },
    { "type": "thought",  "who": "heroine", "text": "Мысль героини." }
  ],
  "choices": [ ... ]
}
```

- `bg` — картинка фона. Пусто/файл не найден → показывается `bgGradient` (плавного перехода достаточно, «битой картинки» не бывает).
- `show` — до 3 персонажей на сцене. Эмоциональные состояния оформляются отдельными ключами вида `hero_smile` с тем же `name` и `color`, что у базового `hero`; в `show` указывается состояние, а в `who` — базовый ключ. Нет `image` у персонажа → круглая монограмма с начальной буквой в его цвете. Говорящий (`who` текущей строки) подсвечивается.
- Типы строк: `narration` (курсив, без имени), `dialogue`, `thought` («Имя · мысли»), `system`. Строка до 240 символов (рекомендуется до 220): длиннее — валидатор предупредит, в плеере блок диалога прокрутится, но ритм чтения пострадает.

### Продолжение сцены — ровно один вариант

| Вариант | Когда |
|---|---|
| `"choices": [...]` | Игрок выбирает |
| `"next": "s5"` | Линейный переход |
| `"branch": [...], "next": "s5"` | Переход по условию шкалы; `next` — обязательный запасной путь |
| `"ending": {title, text, badge}` | Финал истории (засчитывается прохождение и награды) |

### Выбор

```json
{ "text": "До 70 символов", "next": "s5", "crystals": 12,
  "effect":   { "hero": 1 },
  "requires": { "hero": 2 } }
```

- `crystals` — цена в кристаллах (рекомендуются 8 / 10 / 12). Покупка списывается **один раз за прохождение**: если игрок уже платил за этот выбор, повторно не спишется. Не хватает кристаллов → приложение предложит рекламу и после получения само совершит выбор.
- `effect` — прибавки к шкалам `stats` (показываются всплывающей подсказкой «♡ Имя +1»).
- `requires` — минимальные значения шкал. Не выполнено → выбор виден, но заблокирован с подсказкой «Нужно: …».

### Условный переход

```json
"branch": [
  { "if": { "stat": "hero", "gte": 3 }, "to": "ending_love" },
  { "if": { "stat": "brave", "lte": 0 }, "to": "ending_quiet" }
],
"next": "ending_neutral"
```

Поддерживаются сравнения `gte` (≥), `lte` (≤), `eq` (=). Правила проверяются сверху вниз, первое сработавшее выигрывает.

## Экономика (награды игроку)

Все цифры — в `js/config.js`:

- Стартовый бонус: 20 ◆
- Реклама (rewarded): +5 ◆, до 10 в день, пауза 20 сек
- Ежедневный бонус: +5 ◆
- Первое прохождение истории (любой финал): +20 ◆
- Каждый новый финал при перепрохождении: +10 ◆
- Реферал: новичок +15 ◆ за код, пригласивший +20 ◆ после первого прохождения новичка

Отсюда правило цен: платный выбор 10–15 ◆, на историю 4–6 платных выборов — игрок может позволить себе 1–2 сразу, остальные зарабатывает. Так задумано.

## Картинки

| Что | Куда | Формат |
|---|---|---|
| Обложка | `stores/N/cover.jpg` | Вертикаль 2:3, без текста |
| Фон сцены | `stores/N/images/bg-NN.jpg` | Вертикаль 9:16, пустая локация без людей |
| Персонаж | `stores/N/images/<ключ_состояния>.png` | Поясной портрет на однотонном светло-бежевом фоне либо с настоящей прозрачностью; при импорте вырезается в прозрачный WebP-спрайт |

Любая картинка опциональна. Допустимы и внешние URL (`https://…`), но локальные файлы надёжнее и быстрее.

## Проверка перед коммитом

```bash
node tools/validate.mjs stores/5/story.json   # одна история
npm run validate                              # все истории + непрерывность нумерации + наличие картинок
```

Валидатор ловит: ссылки на несуществующие сцены, недостижимые сцены, тупики, дубли `id` между файлами, отсутствующих персонажей/шкалы, слишком длинные строки. Та же проверка встроена в приложение: битый файл не уронит его, а просто не загрузится (в отладочной веб-версии причина видна в блоке «Диагностика» в библиотеке; в Android-сборке ошибка остановит CI ещё раньше).
