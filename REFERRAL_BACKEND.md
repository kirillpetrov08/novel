# Реклама и рефералы: что работает сейчас и как подключить «по-настоящему»

Честно о границах: приложение полностью статическое (нет сервера), поэтому **рефералы между разными телефонами и настоящая реклама физически требуют внешней стороны** — рекламного SDK и маленькой базы данных. Вся логика для них уже написана и изолирована в одном файле `js/backend.js`: подмена реализаций не трогает остальной код.

## Что уже работает без сервера

- Личный реферальный код `NV-XXXXXX` и ссылка `…?ref=NV-XXXXXX` у каждого игрока.
- Друг открывает ссылку → видит баннер → получает +15 ◆ (или вводит код вручную в Профиле).
- Защита от накруток на уровне аккаунта: свой код ввести нельзя, бонус — один раз, формат кода проверяется.
- Факт «новичок прошёл первую историю» фиксируется — именно на него начисляется +20 ◆ пригласившему.
- Реклама: полноценный флоу rewarded-объявления (нельзя закрыть до конца, кулдаун, дневной лимит), вместо SDK — таймер-заглушка на 5 секунд.

**Ограничение локального режима:** выплата пригласившему видна только в реестре того же браузера (localStorage не шарится между устройствами). Для реальных выплат между телефонами подключи базу — ниже план на ~30 минут.

## План подключения настоящего бэкенда (Supabase, бесплатно)

1. Создай проект на supabase.com → Table Editor → таблицы:

```sql
create table players (
  id text primary key,
  ref_code text unique not null,
  referred_by text,
  ref_claimed boolean default false,
  first_completed boolean default false,
  crystals int default 20,
  created_at timestamptz default now()
);
create table crystal_ledger (
  id bigint generated always as identity primary key,
  player_id text references players(id),
  delta int not null,
  reason text,
  created_at timestamptz default now()
);
```

2. Включи Row Level Security и добавь политики «игрок видит/меняет только свою строку» (auth — анонимный вход Supabase Auth, `signInAnonymously()`).

3. В `js/backend.js` замени только тела трёх функций `Referrals.*` на запросы к Supabase REST (`claim` — UPDATE своего игрока + INSERT в ledger; выплата пригласившему — SQL-функция/Edge Function, чтобы нельзя было подделать с клиента; `stats` — SELECT count по `referred_by = мой код`). Интерфейсы и весь UI остаются как есть.

Аналогично подойдёт Firebase (Firestore + Cloud Functions).

## Подключение настоящей рекламы

В `Ads.showRewarded(onTick)` (`js/backend.js`) вместо таймера вызови SDK выбранной сети (Yandex Mobile Ads, AdMob, VK Ads — для веб-обёртки типа Telegram Mini App у Telegram есть свои рекламные форматы) и резолви Promise `true` по событию «реклама досмотрена до конца», `false` — по закрытию. Лимиты, кулдаун и начисление уже реализованы вокруг этого вызова.

## Важно при переходе на сервер

Сейчас баланс хранится на клиенте — для демо и закрытого круга это ок. Как только появятся реальные выплаты/покупки, баланс и все начисления должны переехать на сервер (клиент только отображает), иначе баланс правится одной строкой в консоли браузера.
